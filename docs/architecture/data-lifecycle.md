# 数据生命周期与跨设备开发

代码版本与数据版本分别保存，通过小型版本清单建立对应关系。当前只有来源目录和单文档哈希；整库备份/恢复 CLI 还是任务 42 的占位，不能宣称数据已自动跨设备同步。

| 资产 | 权威位置 | 同步或恢复方式 |
| --- | --- | --- |
| 代码、任务、迁移、评测题、公开来源目录 | Git | 提交并推送；切换到对应代码版本 |
| 原始网页、提取正文、来源元数据 | data/raw/ | 独立拷贝/版本数据包，校验 SHA-256 |
| 正文版本、状态、术语、片段、任务 | MySQL | 一致性逻辑备份；恢复时核对资料/版本/状态 |
| 会话、消息、反馈（未来） | MySQL | 区分开发与真实业务数据，按保留策略备份，不提交 Git |
| 向量索引 | Qdrant | 从 MySQL 已发布版本重建；记录模型/维度/集合版本 |
| 数据备份包（未来） | data/backups/ 或仓库外私有存储 | 单独保存；不直接同步运行中的数据库目录 |
| 基线、评测输出 | artifacts/ | 可重建；重要报告另行归档，摘要可提交 docs |
| 密钥和机器配置 | 本地 .env / 私密配置存储 | 新设备单独配置，不进入普通数据包 |
| 依赖和缓存 | Docker 镜像与本机缓存 | 按锁定版本重建，不复制 node_modules 或虚拟环境 |

## 任务 42 的数据包约定

计划的包内包含 `manifest.json`、`mysql.sql.gz`、`raw/` 和 `SHA256SUMS`。manifest 至少记录：格式版本、创建时间、代码提交、工作区是否干净、Alembic 版本、资料 ID/版本/哈希/状态、各文件相对路径与大小；任务 20 后再记录 embedding/切分/向量集合配置。

小型版本指针与不含正文的清单可随 Git 保存；实际大文件位于私有存储。先实现可导出、可校验、可恢复到空库的最小闭环，再考虑远程同步。恢复前校验路径和哈希，恢复后比较文档数、版本数和状态，再运行 validate_evals。

## 本次已有数据

当前 SQL 手工备份仍位于 data/raw/，且被 Git 忽略。本次目录规划不移动原文、SQL 或 Docker 数据卷，也不更改数据库。新设备仍需要单独复制原文和数据库备份；只拉 Git 不会获得已发布状态。
